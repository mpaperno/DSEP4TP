31/*!
32 \class FSWatcher
33 \ingroup FileSystem
34 \brief The `FSWatcher` class provides an interface for monitoring files and directories for modifications.
35
36 `%FSWatcher` monitors the file system for changes to files
37 and directories by watching a list of specified paths.
38
39 Call `addPath()` to watch a particular file or directory. Multiple
40 paths can be added using the `addPaths()` method. Existing paths can
41 be removed by using the `removePath()` and `removePaths()` methods.
42
43 `%FSWatcher` examines each path added to it. Files that have
44 been added to the `%FSWatcher` can be accessed using the
45 `files()` method, and directories using `directories()`.
46
47 The `fileChanged()` event is emitted when a file has been modified,
48 renamed or removed from disk. Similarly, the `directoryChanged()`
49 event is emitted when a directory or its contents is modified or
50 removed. Note that `%FSWatcher` stops monitoring files once
51 they have been renamed or removed from disk, and directories once
52 they have been removed from disk.
53
54 Keep in mind that the instance of `%FSWatcher` must persist for as long as you need the
55 path(s) to be watched. If the variable holding the instance goes out of scope, it may
56 get garbage-collected at any point and stop emitting events.
57
58 To terminate watching all paths and delete an instance of `%FSWatcher`,
59 use the `destroy()` method and set your instance variable value to `null` or `undefined`.
60
61 See the @ref example_tail for sample usage.
62
63 Notes:
64 - On systems running a Linux kernel without inotify support,
65 file systems that contain watched paths cannot be unmounted.
66 - The act of monitoring files and directories for
67 modifications consumes system resources. This implies there is a
68 limit to the number of files and directories your process can
69 monitor simultaneously. Some system limits the number of open file descriptors to 256
70 by default. This means that `addPath()` and `addPaths()` will fail if
71 your process tries to add more than 256 files or directories to
72 the file system monitor. Also note that your process may have
73 other file descriptors open in addition to the ones for files
74 being monitored, and these other open descriptors also count in
75 the total. MacOS uses a different backend and does not
76 suffer from this issue.
77
78
79 \note The `%FSWatcher` class is a proxy for [QFileSystemWatcher](https://doc.qt.io/qt-6/qfilesystemwatcher.html),
80 part of the underlying Qt C++ library. Most of the documentation text here is originally from
81 the QFileSystemWatcher documentation (used under the GNU Free Documentation License version 1.3).
82
83 \sa File, Dir, @ref example_tail
84 \since v1.3
85*/
86class FSWatcher : public QFileSystemWatcher
87{
88 Q_OBJECT
89 NAMED_EVENT_HANDLER();
90 EVENT_PROPERTY(fileChanged);
91 EVENT_PROPERTY(directoryChanged);
92
93 public:
94
95 //! Constructs a new file system watcher object that isn't monitoring any paths. Path(s) can be added later with `addPath()` or `addPaths()`.
96 Q_INVOKABLE explicit FSWatcher() :
97 QFileSystemWatcher()
98 {
99 setObjectName(QStringLiteral("FSWatcher"));
100 }
101
102 //! Constructs a new file system watcher object which monitors the specified paths list.
103 //! See `addPaths()` for details of how the `paths` argument is treated.
104 Q_INVOKABLE explicit FSWatcher(const QStringList &paths) :
105 QFileSystemWatcher(paths)
106 {
107 setObjectName(QStringLiteral("FSWatcher"));
108 }
109
110 ~FSWatcher() {
111 // qCDebug(lcPlugin) << "Destroyed" << this;
112 }
113
114 /*!
115 Adds `path` to the file system watcher if `path` exists.
116 The path is not added if it does not exist, or if it is already being monitored by this file system watcher.
117
118 If `path` specifies a directory, the `directoryChanged()` event will be emitted when `path` is modified or removed from disk;
119 otherwise the `fileChanged()` event is emitted when `path` is modified, renamed or removed.
120
121 If the watch was successful, `true` is returned.
122
123 Reasons for a watch failure are generally system-dependent, but may include the resource not existing,
124 access failures, or the total watch count limit, if the platform has one.
125
126 \sa addPaths(), removePath()
127 */
128 Q_INVOKABLE bool addPath(const QString &path) { return QFileSystemWatcher::addPath(path); }
129
130 /*!
131 Adds each path in \a paths to the file system watcher.
132 Paths are not added if they do not exist, or if they are already being monitored by the file system watcher.
133
134 If a path specifies a directory, the `directoryChanged()` signal will be emitted when the path is modified or removed from disk;
135 otherwise the `fileChanged()` signal is emitted when the path is modified, renamed, or removed.
136
137 The return value is a list of paths that could __not__ be watched.
138
139 Reasons for a watch failure are generally system-dependent, but may include the resource not existing,
140 access failures, or the total watch count limit, if the platform has one.
141
142 \note There may be a system dependent limit to the number of files and directories that can be monitored simultaneously.
143 If this limit has been reached, the excess \a paths will not be monitored, and they will be added to the returned list.
144
145 \sa addPath(), removePaths()
146 */
147 Q_INVOKABLE QStringList addPaths(const QStringList &paths) { return QFileSystemWatcher::addPaths(paths); }
148
149 /*!
150 Removes the specified \a path from the file system watcher.
151 If the watch is successfully removed, `true` is returned.
152
153 Reasons for watch removal failing are generally system-dependent, but may be due to the path having already been deleted, for example.
154 \sa removePaths(), addPath()
155 */
156 Q_INVOKABLE bool removePath(const QString &path) { return QFileSystemWatcher::removePath(path); }
157
158 /*!
159 Removes the specified \a paths from the file system watcher.
160 The return value is a list of paths which were __not__ able to be un-watched successfully.
161
162 Reasons for watch removal failing are generally system-dependent, but may be due to the path having already been deleted, for example.
163 \sa removePath(), addPaths()
164 */
165 Q_INVOKABLE QStringList removePaths(const QStringList &paths) { return QFileSystemWatcher::removePaths(paths); }
166
167 /*!
168 Returns a list of paths to directories that are being watched.
169 \sa files()
170 */
171 Q_INVOKABLE QStringList directories() const { return QFileSystemWatcher::directories(); }
172 /*!
173 Returns a list of paths to files that are being watched.
174 \sa directories()
175 */
176 Q_INVOKABLE QStringList files() const { return QFileSystemWatcher::files(); }
177
178 //! Stops watching all paths and destroys this instance of FSWatcher. Trying to use this instance after calling `destroy()` is undefined behavior.
179 Q_INVOKABLE void destroy() { this->deleteLater(); }
180
181 /*!
182 \name Events
183 See \ref EventHandlers for details about connecting handlers to events.
184 \{
185
186 \fn void FSWatcher::fileChanged(string path)
187 \memberof FSWatcher
188 This event is emitted when the file at the specified \a path is modified, renamed or removed from disk.
189
190 \note As a safety measure, many applications save an open file by writing a new file and then deleting the old one.
191 In your handler function, you can check if `watcher.files().contains(path)`.
192 If it returns \c false, check whether the file still exists and then call \c addPath() to continue watching it.
193 \sa directoryChanged()
194
195
196 \fn void FSWatcher::directoryChanged(string path)
197 \memberof FSWatcher
198 This event is emitted when the directory at a specified \a path is modified (e.g., when a file is added or deleted) or removed from disk.
199
200 Note that if there are several changes during a short period of time, some of the changes might not emit this event.
201 However, the last change in the sequence of changes will always generate this event.
202 \sa fileChanged()
203
204 \}
205 */
206};
