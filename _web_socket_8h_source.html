65/*!
66 \class WebSocket
67 \ingroup NetAPI
68 \since 1.3
69
70 \brief Implementation of the [WebSocket Web API](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket)
71
72 _WebSockets_ is a web technology providing full-duplex communications channels over a single TCP connection.
73
74 The %WebSocket object provides the API for creating and managing a %WebSocket connection to a server, as well as for sending and receiving data on the connection.
75
76 This implementation replicates all of the standard interface and most of the behavior and options, except as noted below. There are also many additions,
77 some of which replicate the Node-js [websockets/ws](https://github.com/websockets/ws/blob/master/doc/ws.md) implementation.
78
79 ### Major differences vs. typical standard implementations:
80
81 - The socket is _not_ automatically opened when a `WebSocket` instance is created. __You must explicitly call the `open()` method to initiate a connection.__
82 Do this _after_ connecting all your event listeners/handlers.
83 - `WebSocket` doesn't throw any exceptions. All errors are reported in the `error` event.
84 - HTTP redirects are not supported (WebSocket will report an "Unhandled http status code: 301" error). This includes redirects from `ws:` to `wss:` protocol URLs.
85 - The `binaryType` property only supports "arraybuffer", which is the default. (Note that a new type "fragments" is available, similar to the Node-js version).
86 - A connected `WebSocket` instance automatically responds to all "ping" messages from the server.
87 - No websocket protocol "extensions" are supported, notably _per-message-deflate_ (compression of individual messages).
88 (Note that extensions are _not_ the same as "sub-protocols" describing the message exchange format, such as "json" or "xml".)
89
90 ### Example
91
92 Exchange messages with an "echo" WebSockets server.
93 ```js
94 // Create instance and specify the server URL. This public "echo" service sends back whatever we send it.
95 const ws = new WebSocket('wss://websocket-echo.com/');
96
97 // The "open" event is triggered once a connection to the server is established.
98 ws.onopen = function() {
99 console.log('WebSocket client connected at', Date.now());
100 // Send a text message with the current timestamp.
101 ws.send(Date.now());
102 };
103
104 // The "message" event is triggered when a message arrives from the server.
105 // In this case it will be the echo reply to the message we sent in the "open" event handler above.
106 ws.onmessage = function(messageEvent) {
107 // Prints the time difference between current time and the time we sent to the echo server.
108 console.log(`Round-trip time: ${Date.now() - messageEvent.data} ms`);
109 // Once we're done with the socket, close it. The code and reason are optional.
110 ws.close(1000, "Finished!");
111 };
112
113 // The "close" event happens when the socket disconnects.
114 ws.onclose = function(closeEvent) {
115 console.log(`Disconnected at ${Date.now()} with code: ${closeEvent.code} reason: ${closeEvent.reason || "[none given]"}`);
116 // This is a good place to delete the WebSocket instance __if we're not going to use it again__.
117 ws = null;
118 };
119
120 // Error handler. The argument would be an instance of a generic `Error` type. Just connect to console output for this example.
121 ws.onerror = console.error;
122
123 // Start the connection
124 ws.open();
125 ```
126*/
